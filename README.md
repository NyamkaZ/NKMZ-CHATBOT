# AI Chatbot Platform

Multi-channel AI chatbot with ChatGPT-like UI, background generation, usage limits, RAG, and admin panel.

## Features

- **Website UI** – Dark/light mode, sidebar with searchable recent chats, streaming responses, “Thinking…” state
- **Neutral visual design** – Black, gray and white surfaces; React Bits LetterGlitch on login/register, PixelCard prompt suggestions, and ElectricBorder around the auth card and focused chat composer.
- **Pinned chats & dated history** – Pin conversations to the top; the rest is grouped into Today / Yesterday / Previous 7 days / Older
- **Search inside messages** – The sidebar search matches chat titles and message text
- **Code blocks** – Syntax highlighting, language label and one-click copy in answers
- **Profile** (`/profile`) – Edit your display name and change your password
- **Account recovery** – “Forgot password” emails a single-use link (30 min); new accounts get an address-confirmation link. Changing or resetting a password signs out other devices. Needs `SMTP_*` settings; without them, development prints the link in the backend log
- **Sign-in protection** – Emails are case-insensitive; an account is locked for 15 minutes after 8 failed sign-ins
- **Concurrent chat navigation** – Switch chats while generation continues in the background; return anytime without losing state
- **One message at a time per conversation** – Input disabled until the previous response finishes
- **Message actions** – Stop generating, Regenerate, Copy, Retry on failure
- **Auth** – Guest (3 free messages, `GUEST_MESSAGE_LIMIT`) → Login required; guest chats auto-linked on login. New guest sessions are limited per IP (`GUEST_SESSIONS_PER_IP_PER_HOUR`)
- **Usage limits** – 30 messages/day for free users (Redis + DB), rate limiting
- **Subscriptions** – Free / Pro / Premium tiers via **Stripe** (or **demo upgrade** in dev); `/pricing` UI
- **Personas** – Code, tutor, creative, analyst modes in the chat input
- **Command palette** – `Ctrl+K` (new chat, export Markdown, pricing, install app)
- **Installable (PWA)** – Web manifest and icons; “Install app” in the palette where the browser supports it. In production builds a small service worker shows an offline page when navigation fails (it never caches `/api`)
- **Voice input** – Browser speech-to-text (Chrome/Edge)
- **Auto chat titles** – Generated by the model after the first exchange
- **Admin panel** (`/admin`) – Users, system health (Postgres / Redis / Ollama), analytics
- **Multi-channel** – Telegram & Discord bots (same backend)
- **RAG** – ChromaDB + multilingual embeddings; document upload API (txt/md/pdf) indexes into the knowledge base
- **Delete chats** – remove conversations from the sidebar
- **Primary model** – Ollama **Qwen3 8B** (`qwen3:8b`) with optional thinking mode
- **Stack** – FastAPI · Next.js 15 · PostgreSQL · Redis · Ollama · Docker Compose

LetterGlitch uses a lightweight Canvas 2D character animation when WebGL cannot initialize. Both renderers respect reduced-motion preferences; decorative canvases stay outside keyboard navigation.

## Quick Start

### Prerequisites

- Docker & Docker Compose
- ~10–16 GB RAM recommended (Qwen3 8B Q4 ≈ 5.2 GB weights + runtime headroom)

### 1. Clone / enter project

```bash
cd ai-chatbot-platform
cp .env.example .env
# Edit SECRET_KEY and optional bot tokens
```

### 2. Start infrastructure + apps

```bash
docker compose up -d --build
```

The backend reads the root `.env`; Compose supplies container addresses for Postgres, Redis, and Ollama. The default CPU setup uses a 4096-token context. For NVIDIA acceleration, use `docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build`.

### 3. Pull the LLM model (first time)

```bash
./scripts/init_ollama.sh
# or:
docker exec -it chatbot-ollama ollama pull qwen3:8b
docker exec -it chatbot-ollama ollama pull nomic-embed-text
```

### 4. Open the app

- Frontend: http://localhost:3000  
- API docs: http://localhost:8000/docs  
- Admin: http://localhost:3000/admin (create an admin user first)

### Create an admin user

```bash
docker exec -it chatbot-backend python -c "
import asyncio
from app.core.database import AsyncSessionLocal
from app.models.user import User, UserRole
from app.core.security import get_password_hash
from getpass import getpass

async def main():
    async with AsyncSessionLocal() as db:
        u = User(
            email='admin@example.com',
            hashed_password=get_password_hash(getpass('Admin password: ')),
            full_name='Admin',
            role=UserRole.ADMIN,
            is_guest=False,
        )
        db.add(u)
        await db.commit()
        print('Admin created: admin@example.com')
asyncio.run(main())
"
```

## Architecture highlights

### Background generation + free navigation

1. Client POSTs to `/api/v1/chats/send` → backend creates user + assistant messages, starts an asyncio task.
2. Task streams from Ollama, writes tokens to Redis and publishes on a Redis channel.
3. Client opens an EventSource to `/api/v1/stream/{generation_id}`.
4. User can leave the chat; generation continues. On return, the stream endpoint replays already-produced tokens then continues live.
5. Per-chat Redis lock ensures only one generation runs at a time for a conversation.

### Limits

- Daily message counter in Redis (key per user per UTC day) + short rate-limit window.
- Guests may send `GUEST_MESSAGE_LIMIT` messages (default 3); after that login is required.
- A 429 response carries `Retry-After` (seconds); the composer shows it as a countdown.

## Development without full Docker

### About NKMZ and the Horizon scene

The `/about` page introduces NKMZ and its chat product in Mongolian and English. Open it from the company's About link in the chat header. The opening section zooms the crimson orbit as you scroll, and the product section uses the Horizon star field and mountains.

The project already includes TypeScript, Tailwind CSS, and shadcn configuration in `frontend/components.json`; no setup migration is needed. Reusable UI components live in `frontend/components/ui`, with global styles in `frontend/app/globals.css`. The Horizon component uses the installed `three`, `@types/three`, and `gsap` packages, and needs no extra provider or image assets. Its star field and mountains are generated in the scene.

Use `HorizonHeroSection` with children for custom content, or import `Component` from `@/components/ui/horizon-hero-section` for the standalone three-section demo. `DemoOne` in `frontend/components/ui/demo.tsx` demonstrates that import. ## Telegram / Discord

Set `TELEGRAM_BOT_TOKEN` / `DISCORD_BOT_TOKEN` in `.env` (or compose environment) and run:

```bash
# from host (with network access to backend)
python bots/telegram/bot.py
python bots/discord/bot.py
```

Or add worker services to `docker-compose.yml`.

The adapters create real guest sessions and retain the conversation during the bot process lifetime. The guest message limit applies; continued use requires the website. Messenger is currently an unimplemented webhook scaffold.

## Checks

```bash
cd frontend
npm ci
npm test
npm run lint
npm run typecheck
npm run build

cd ../backend
python -m pip install -r requirements.txt -r requirements-test.txt
python -m pytest -q
```

Backend regression tests use a temporary SQLite database and fake Redis. Live generation requires the Compose services and downloaded Ollama models. API health is at `/health`; model readiness is at `/health/ollama`.

If an existing frontend container retains an older Next.js version or reports a missing package after an update, refresh its generated dependency/cache volumes with `docker compose up -d --build --renew-anon-volumes --no-deps frontend` from the project root. This refreshes only the frontend runtime; database and chat records stay in their existing volumes.

The development frontend enables `WATCHPACK_POLLING` so source edits on Windows bind mounts trigger a rebuild.

The dependency audit still flags upstream Chroma server authorization advisories (PYSEC-2026-3813, PYSEC-2026-3814, PYSEC-2026-3815), which currently have no published fix. This application uses an embedded `PersistentClient`; Compose does not expose a Chroma server. Reassess these advisories before introducing a standalone Chroma service. Live Stripe payments and bot delivery require configured provider credentials; Messenger remains a scaffold.

The default in-process generation mode uses one backend process. Startup marks interrupted jobs as failed so the latest response can be retried, including a failed guest answer. For independent worker deployments, enable `USE_GENERATION_WORKER` on the API and run the worker with the same `.env`, database, Redis, Ollama, and knowledge-base settings.

## Notes / Production checklist

- Change `SECRET_KEY` and DB passwords.
- Put a reverse proxy (Traefik / Caddy / Nginx) in front of frontend + backend.
- For multi-worker backend, the generation stop flags should be fully Redis-based (already mostly are).
- Consider Celery / ARQ for very long-running or high-concurrency generation jobs.
- GPU for Ollama: uncomment the deploy/resources section in `docker-compose.yml`.
- Facebook Messenger can be added as another thin adapter that calls the same `/chats/send` API.

# AI Chatbot Platform

Production-ready multi-channel AI chatbot with ChatGPT-like UI, background generation, usage limits, RAG, and admin panel.

## Features

- **Website UI** – Dark/light mode, sidebar with searchable recent chats, streaming responses, “Thinking…” state
- **Concurrent chat navigation** – Switch chats while generation continues in the background; return anytime without losing state
- **One message at a time per conversation** – Input disabled until the previous response finishes
- **Message actions** – Stop generating, Regenerate, Copy, Retry on failure
- **Auth** – Guest (1 free message) → Login required; guest chats auto-linked on login
- **Usage limits** – 30 messages/day for free users (Redis + DB), rate limiting
- **Subscriptions** – Free / Pro / Premium tiers via **Stripe** (or **demo upgrade** in dev); `/pricing` UI
- **Personas** – Code, tutor, creative, analyst modes in the chat input
- **Command palette** – `Ctrl+K` (new chat, export Markdown, theme, pricing)
- **Voice input** – Browser speech-to-text (Chrome/Edge)
- **Auto chat titles** – Generated by the model after the first exchange
- **Admin panel** (`/admin`) – Users, system health (Postgres / Redis / Ollama), analytics
- **Multi-channel** – Telegram & Discord bots (same backend)
- **RAG** – ChromaDB + multilingual embeddings; document upload API (txt/md/pdf) indexes into the knowledge base
- **Delete chats** – remove conversations from the sidebar
- **Primary model** – Ollama **Qwen3 8B** (`qwen3:8b`) with optional thinking mode
- **Stack** – FastAPI · Next.js 14 · PostgreSQL · Redis · Ollama · Docker Compose

## Quick Start

### Prerequisites

- Docker & Docker Compose
- ~10–16 GB RAM recommended (Qwen3 8B Q4 ≈ 5.2 GB weights + runtime headroom)

### 1. Clone / enter project

```bash
cd ai-chatbot-platform
cp .env.example .env
# Edit SECRET_KEY and optional bot tokens
```

### 2. Start infrastructure + apps

```bash
docker compose up -d --build
```

### 3. Pull the LLM model (first time)

```bash
./scripts/init_ollama.sh
# or:
docker exec -it chatbot-ollama ollama pull qwen3:8b
docker exec -it chatbot-ollama ollama pull nomic-embed-text
```

### 4. Open the app

- Frontend: http://localhost:3000  
- API docs: http://localhost:8000/docs  
- Admin: http://localhost:3000/admin (create an admin user first)

### Create an admin user

```bash
docker exec -it chatbot-backend python -c "
import asyncio
from app.core.database import AsyncSessionLocal
from app.models.user import User, UserRole
from app.core.security import get_password_hash

async def main():
    async with AsyncSessionLocal() as db:
        u = User(
            email='admin@example.com',
            hashed_password=get_password_hash('admin123'),
            full_name='Admin',
            role=UserRole.ADMIN,
            is_guest=False,
        )
        db.add(u)
        await db.commit()
        print('Admin created: admin@example.com / admin123')
asyncio.run(main())
"
```

## Architecture highlights

### Background generation + free navigation

1. Client POSTs to `/api/v1/chats/send` → backend creates user + assistant messages, starts an asyncio task.
2. Task streams from Ollama, writes tokens to Redis and publishes on a Redis channel.
3. Client opens an EventSource to `/api/v1/stream/{generation_id}`.
4. User can leave the chat; generation continues. On return, the stream endpoint replays already-produced tokens then continues live.
5. Per-chat Redis lock ensures only one generation runs at a time for a conversation.

### Limits

- Daily message counter in Redis (key per user per UTC day) + short rate-limit window.
- Guests may send only the first message; subsequent messages require login.

## Development without full Docker

cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head

```

hits = await query_knowledge("user question")
context = build_rag_context(hits)
# Inject `context` into the system prompt of the generation task
```

## Notes / Production checklist

- Change `SECRET_KEY` and DB passwords.
- Put a reverse proxy (Traefik / Caddy / Nginx) in front of frontend + backend.
- For multi-worker backend, the generation stop flags should be fully Redis-based (already mostly are).
- Consider Celery / ARQ for very long-running or high-concurrency generation jobs.
- GPU for Ollama: uncomment the deploy/resources section in `docker-compose.yml`.
- Facebook Messenger can be added as another thin adapter that calls the same `/chats/send` API.
